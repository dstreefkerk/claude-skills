# Slide Notes Guidance — Full Reference

## 1. Notes as a Runbook, Not a Script

Speaker notes should function like a structured prompt, not a word-for-word script.

**Do:**

* Use bullet prompts, not paragraphs
* Include key phrases, not full sentences
* Add reminders of transitions and emphasis points
* Capture technical nuance you don't want to forget

**Avoid:**

* Writing an essay to be read verbatim
* Duplicating exactly what's on the slide

Optimise for fast scanning under pressure.

## 2. Add Context That Isn't On the Slide

Slides should be sparse. Notes are where the depth lives.

Use notes to store:

* Architecture caveats
* Version dependencies
* Real-world examples
* Edge cases
* Assumptions
* Threat model boundaries
* "This breaks if..." warnings

The slide states the point. The notes defend it technically.

## 3. Pre-Bake Answers to Likely Questions

Include:

* Anticipated objections
* Common misconceptions
* "Yes, but what about..." rebuttals
* Performance or scaling constraints
* Trade-offs

Think of it as a defensive layer — especially when presenting strong opinions.

## 4. Capture Data Sources and References

In notes:

* Record report names
* Link to research (even if not shown)
* Include CVE numbers
* Note standards references (e.g. RFC numbers)

This prevents fuzzy answers, guessing under pressure, and "I'll have to check that later."

## 5. Mark Emphasis and Tone Cues

In notes:

* Mark strong statements clearly
* Note where to slow down
* Highlight where a diagram needs explanation
* Flag slides that require storytelling

Example cues:

* ⚠ Stress this is *detection*, not prevention
* Pause after diagram explanation
* Emphasise operational cost

## 6. Use Notes for Transition Control

Add to notes:

* Why this slide follows the previous one
* The thread being carried forward
* What the audience should now understand

This avoids topic drift, abrupt jumps, and losing the narrative.

## 7. Store Demo Guardrails (If Applicable)

If demoing, include:

* Exact command syntax
* Expected output
* Fallback explanation if demo fails
* What to skip if time compresses

Never rely on memory for live technical steps.

## 8. Add Time Markers

For conference or client slots:

* Note target time at specific slides
* Mark optional slides
* Flag sections that can compress

Example: "10 min mark here", "Optional deep dive", "Can summarise in 60 sec if needed"

## 9. Keep Notes Clean and Structured

Use:

* Short bullets
* Clear spacing
* Sub-bullets for detail
* Visual markers for emphasis

Avoid dense paragraphs.

## 10. Review Notes Like an Incident Report

Before delivery:

* Remove fluff
* Tighten phrasing
* Check technical accuracy
* Ensure terminology consistency
* Verify version references

Notes should read like a disciplined briefing document, not brainstorming.

## 11. What Not to Put in Notes

* Personal jokes you might regret
* Anything embarrassing if exported
* Overly long explanations you'll never say
* Unverified claims

Notes can be shared unintentionally.
